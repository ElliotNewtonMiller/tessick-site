Features

Reports that say what changed

Each run is compared with the one before: new failures, fixes and tests still failing. Trends, flaky and slow tests and each case's history are a click away, or emailed on a schedule.

About the reports →

Results straight from CI

Send your tests' JUnit XML report with one request, and a run named after the build appears. JSON works too, with screenshots, videos and logs attached.

CI examples →

Test cases with versions

Steps, preconditions and summary are versioned, from draft to approved. Editing an approved case makes a new draft, and approving it updates every active plan.

Evidence on every result

Paste a screenshot or drop files on the case you're testing. Screenshots, videos, logs and Playwright traces are kept with the result, from people or from CI.

AI agents that write drafts

Ask an agent such as Claude Code, over MCP, to write test cases: they arrive as drafts for a person to approve. It can also read reports and record results, within its token's permissions.

Try It in a Minute

Two commands and Docker. A demo project comes loaded, with eight runs of results and an open run to try the keyboard on.

Terminal
$ curl -fsSLO https://raw.githubusercontent.com/ElliotNewtonMiller/Tessick/main/docker-compose.demo.yml
$ docker compose -f docker-compose.demo.yml up

Then open http://localhost:3001 and sign in as admin / tessick-demo-admin. It listens only on your machine, and docker compose -f docker-compose.demo.yml down -v removes it.

For real data, follow the deployment guide: Docker Compose with PostgreSQL, or Node.js 22.
