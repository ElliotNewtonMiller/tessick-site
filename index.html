Try it in a minute

Easy Demo

With Docker and nothing to configure. A demo project comes loaded, with eight runs of results to explore and an open run to try the keyboard on.

Terminal
$ curl -fsSLO https://raw.githubusercontent.com/ElliotNewtonMiller/Tessick/main/docker-compose.demo.yml
$ docker compose -f docker-compose.demo.yml up

Then open http://localhost:3001 and sign in as admin / tessick-demo-admin. The demo listens only on your own machine, and docker compose -f docker-compose.demo.yml down -v removes it all.

To keep real data, run it for real: Tessick and PostgreSQL with Docker Compose, or Node.js 22 without Docker.

What you get

Modern Features

Reports

Reports that say what changed

Each run is compared with the one before: new failures, fixes and tests still failing, with their messages. Trends across runs, flaky and slow tests, and every case's history are a click away, and can be emailed on a schedule.

About the reports →
CI

Results straight from CI

Your tests already write a JUnit XML report: send it to Tessick with one request. A run named after the build is created on first use, and its results show in the app as soon as you look. JSON works too, with screenshots, videos and logs attached.

CI examples for GitHub Actions, GitLab, Jenkins and Azure DevOps →
Specification

Test cases with versions

A case's steps, preconditions and summary are versioned, from draft to approved. Editing an approved case makes a new draft, and approving it updates the case in every active plan. Duplicate a case to start from one you have.

Execution

Evidence on every result

Paste a screenshot or drop files on the case you're testing: up to 50 on each result. Screenshots, videos, logs and Playwright traces are kept with it, from people or from CI, on disk or in S3-compatible storage.

AI agents

AI agents that write drafts

Connect an agent such as Claude Code over MCP, and ask it to write test cases. They arrive as drafts for a person to review and approve. An agent can also read reports and record results, with only the permissions its token gives it.

And more

Custom fields

Six types on cases and suites, for every project or chosen ones, with required fields and defaults.

Roles and permissions

Editable roles, a different role per project, and per-user overrides.

API tokens

Each bound to one project and limited to the capabilities you choose, for CI and agents.

Webhooks

Runs finishing, tests failing and imports, sent to Slack, Teams or your own code, signed and retried.

Scheduled reports

Reports emailed daily or weekly to whoever needs them, or sent once from the Reports view.

Import and export

TestLink XML, JUnit XML, TestRail CSV, CSV and JSON in; JSON and CSV out.

Test plans and runs

A plan pins its cases at a version; each run records who did what, when.

REST API

Everything the app does, with an interactive reference page on every server.
