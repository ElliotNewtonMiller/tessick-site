Moving from TestLink to Tessick

TestLink has organized a lot of teams' testing for a long time. When you're ready for something new, Tessick takes your test cases across with their ids, and, if you want them, your history, users and scripts too.

XML Import

No scripts and no database access:

  1. In Tessick, create a project with the same prefix as in TestLink, so SHOP-331 stays SHOP-331.
  2. In TestLink's Test Specification, click the project and Export All Test Suites as XML, with keywords and custom fields.
  3. In Tessick, click Import and choose the file. The preview shows what will be created and writes nothing.
  4. Decide what each TestLink custom field becomes, then Run Import.

Importing the same file again later gives the cases already there a new version instead of making copies, so you can keep TestLink in use while you try Tessick out.

Database Migration

A migration script reads TestLink 1.9's database (MySQL, MariaDB or PostgreSQL) and moves it into Tessick in one transaction, keeping TestLink's ids.

What it brings

Users and roles, projects, suites, every case version, custom fields, keywords, test plans, builds, and results with their testers and times. Users' TestLink API keys keep working.

Try it safely

Run it with --dry-run first: it does everything, prints exactly what it would bring, and writes nothing. Run it early, then again at the switch: a second run brings only what TestLink gained since.

Good to know

Passwords aren't brought, as TestLink stores them as unsalted MD5: an admin sets them again. Requirements, attachments, milestones and tester assignments stay behind, and each build and platform becomes its own test run.

Day-one compatible

Keep Your Scripts

Tessick answers TestLink's REST API, in its v1, v2 and custom versions, under the same /lib/api/rest/ paths, with the same ids, bodies and answers. A script, CI job or Postman collection written for it keeps working when it's pointed at Tessick:

testlink.example.com/lib/api/rest/custom/testprojects
tessick.example.com/lib/api/rest/custom/testprojects

Each user's TestLink API key comes across with the migration, or they make one in Tessick. Tessick doesn't answer TestLink's older XML-RPC API.

What's different once you've moved

  • Builds are test runs, and a test plan has as many as you like.
  • Recording results is keyboard-driven: j/k move through the queue, and p/f/b/s record pass, fail, blocked or skipped.
  • CI sends its JUnit XML report straight to a run, created by build name on first use.
  • A case's content is versioned: editing an approved case makes a new draft to approve.
  • Reports are built in: run comparisons, trends, flaky and slow tests, emailed on a schedule if you like.

Questions

Do my test case ids change?

No. Create the Tessick project with the same prefix as in TestLink, and SHOP-331 stays SHOP-331. If an id is already taken in the project, that case gets the next free number. The database migration keeps TestLink's ids too.

Do my automation scripts keep working?

Scripts written for TestLink's REST API (v1, v2 and custom) do, with only the host changed and the user's TestLink API key. Tessick doesn't answer the older XML-RPC API. Tessick's own API also takes JUnit XML reports straight from CI.

Can I try it without changing TestLink?

Yes. The XML export only reads from TestLink, and the migration reads a copy of its database. The demo runs on your own machine with two commands.

Do I have to move everything at once?

No. Export one suite or one project at a time, and import the same file again after later edits in TestLink without making copies. With the migration, a second run brings only what's new. Just edit each case in one place.

What does it cost?

Nothing. Tessick is open source under the AGPL-3.0 and runs on your own server. A commercial license is available for organizations that need other terms: ask at TessickTesting@gmail.com.
