XML Import

About 15 minutes, with no scripts and no database access:

  1. In Tessick, create a project with the same prefix as in TestLink, so SHOP-331 stays SHOP-331. An id already taken gets the next free number.
  2. In TestLink's Test Specification, Export All Test Suites as XML, with keywords and custom fields.
  3. In Tessick, click Import and choose the file. The preview writes nothing.
  4. Decide what each custom field becomes, then Run Import.
  5. Export each test plan from TestLink's Test Plan Management and import it the same way. The preview offers to approve its draft cases, since a plan takes approved ones.

Database Migration

A script reads TestLink 1.9's database (MySQL, MariaDB or PostgreSQL) and moves it in one transaction, keeping TestLink's ids.

  • It brings users and roles, projects, every case version, custom fields, keywords, plans, builds, and results with their testers and times.
  • --dry-run prints what it would bring and writes nothing. A second run brings only what TestLink gained since.
  • Passwords aren't brought (TestLink keeps unsalted MD5): an admin sets them again.
  • Left behind: requirements, attachments, milestones and tester assignments. Each build and platform becomes a test run.

Keep Your Scripts

Tessick answers TestLink's REST API (v1, v2 and custom) under the same /lib/api/rest/ paths, with the same ids and answers. Scripts, CI jobs and Postman collections need only the host changed, with the user's TestLink API key (brought by the migration, or made in Tessick). The older XML-RPC API isn't answered.

Questions

Can I try it without changing TestLink?

Yes. The XML export only reads from TestLink, and the migration reads a copy of its database. The demo runs on your own machine.

Do I have to move everything at once?

No. Importing the same file again updates the cases already there instead of copying them, and a second migration run brings only what's new, so TestLink can stay in use meanwhile. Just edit each case in one place.
